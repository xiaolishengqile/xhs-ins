# 本机网页管理与静默采集方案

状态：用户确认只在本机使用网页，要求开始修改；普通采集不得显示博主主页。

## 目标

用现有本机网页取代原生桌面界面，保留独立采集后台。关闭管理页后任务继续运行。普通采集始终使用隐藏浏览器；仅用户在等待登录或验证时主动点击按钮，才显示专用登录窗口。采集仍需在后台访问主页以发现内容。

## 架构

- Node.js 后台是任务、断点、图片索引和设置的唯一写入者；网页只调用回环地址接口。
- 网页提供任务、图片、设置三个入口。现有任务接口和数据格式保留，不迁移 `.data`。
- 图片接口只接受账号和文件名两个单段标识；遍历结果、符号链接、非图片和超限文件均拒绝。缩略图由后台按需生成并限制大小，原图只读。
- 设置保存默认日期范围及“下次后台启动的图片目录”。运行中的实际目录不变，网页明确显示二者；安全停止后由启动入口重新启动才生效。
- 后台停止接口先答复网页，再执行现有安全关闭流程。启动脚本负责启动或复用后台并打开网页；微软托盘作为可选入口保留。
- 移除原生桌面运行层和其专属自动化，维护一套网页界面。

## 验收

1. 本机网页可完成原任务流程、浏览已保存图片、查看和保存设置、触发安全停止。
2. 普通采集在任何环境变量下都不显示博主主页；登录窗口只能由用户显式操作打开。
3. 图片接口不能读取根目录外、符号链接、非图片或超限文件；损坏图片不会导致后台崩溃。
4. 关闭网页不影响后台任务；现有 `.data` 和图片不被迁移或删除。
5. 隔离目录下的接口、网页与后台流程测试通过；现有全套测试通过。
