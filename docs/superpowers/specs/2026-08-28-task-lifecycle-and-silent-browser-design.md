# 采集任务完整生命周期与静默运行设计

## 背景

当前系统把“输入或导入链接”和“开始采集”绑定在一起。前端创建任务后，任务管理器立即将任务放入运行队列；浏览器默认以可见方式启动，采集器还会主动把页面切到前台。全局暂停只停止任务，没有释放平台共用的浏览器上下文。采集结果则分散在任务编号目录和多个压缩包中，不方便按博主管理。

这会造成三个问题：用户无法在运行前检查任务；批量导入后立即产生大量访问；暂停后仍保留采集浏览器，影响其他工作。

## 目标

1. 单条输入和文件导入都先形成可检查的“待开始”任务。
2. 只有用户明确点击开始，任务才进入并发队列。
3. 默认静默采集，不显示窗口、不抢占前台。
4. 只有登录或验证需要人工操作时，才由用户主动打开专用登录窗口。
5. 暂停全部后停止运行和排队任务，并关闭采集器持有的浏览器资源。
6. 采集器始终使用项目独立的账号目录，不读取或关闭用户日常浏览器。
7. 内置用户提供的七百一十九个唯一博主主页，无需重复上传文档。
8. 图片直接保存到本机统一目录，并按博主账号建立子目录。
9. 用户结果目录只保存图片，不生成明细表或任务压缩包。

## 用户流程

### 输入或导入

1. 用户粘贴一条或多条博主主页链接，或者选择链接文件。
2. 文件只负责解析，解析结果回填到链接输入区，并显示有效、重复、无效数量，不创建任务。
3. 页面提供“加载内置博主（719）”按钮。点击后把内置主页加载到预览区，不创建任务、不启动浏览器。
4. 用户检查链接、选择采集周期，点击“加入待采集”。
5. 系统创建“待开始”任务，但不启动浏览器。

输入区统一支持最多五百个唯一链接；“最多并发五个”只表示同时运行数量，不再被误解为一次只能提交五条。

内置名单超过单次五百条限制，因此页面分批提交到服务端；任务仍按统一列表展示，由用户勾选后开始。内置名单以项目数据文件保存，内容来自用户提供的《INS博主主页链接汇总》文档；文档中的可见链接和跳转目标重复出现，内置前按标准主页地址去重为七百一十九条。

### 本地图片保存

1. 正式运行方式为用户电脑上的本地服务，不依赖云端函数保存图片。
2. 结果根目录固定为 `/Users/lijiawei/Pictures/博主图片采集`。
3. 每个博主使用主页账号名建立子目录。账号名经过文件名安全处理，但不改动可识别部分。
4. 图片在博主目录内连续编号，命名格式为 `账号名_000001_点赞123.扩展名`。
5. 点赞数未公开时使用“点赞未知”；同一笔记的多张图片使用不同序列号，但沿用该笔记的点赞数。
6. 文件名中的点赞数是首次保存时的采集快照，后续重复采集不因点赞变化重命名旧文件。
7. 系统按“平台、账号、笔记编号、图片序号”去重，重复运行不会重复写入图片。
8. 用户结果目录不生成采集明细表、笔记数据文件或压缩包。收藏数、评论数和原文链接不再作为结果文件保存。
9. 任务状态与去重索引继续保存在项目内部数据目录，不混入用户图片目录。

### 开始与暂停

1. 每个“待开始”任务提供“开始”按钮。
2. 任务列表支持勾选，并提供“开始选中”按钮。
3. 点击开始后，任务依次进入等待队列，最多同时运行五个。
4. 点击“暂停全部”后：
   - 先禁止调度新任务；
   - 中止正在运行的任务；
   - 把等待和运行任务统一保存为“已暂停”；
   - 等待任务清理页面；
   - 关闭采集器专用浏览器。
5. 点击“继续全部”后，已暂停任务重新进入等待队列，并从头采集，避免断点状态不完整。

### 登录与验证

1. 静默采集检测到未登录或安全验证时，关闭当前任务页面并把任务置为“等待人工处理”。
2. 任务卡片显示“打开登录窗口”。只有用户点击后，系统才启动可见的专用浏览器并进入对应平台登录页。
3. 用户完成登录或验证后，点击“我已处理，继续”。系统关闭可见窗口，重新以静默方式启动采集，并复用同一独立账号目录中的登录状态。
4. 同一平台处于人工登录期间，不启动该平台的新任务；另一个平台不受影响。

## 状态模型

新增 `pending` 状态，对应界面文案“待开始”。

状态转换如下：

- 创建任务：`pending`
- 用户开始：`pending → queued → running`
- 全局暂停：`queued/running → paused`
- 继续全部：`paused → queued`
- 需要登录：`running → waiting_user`
- 人工处理完成：`waiting_user → queued`
- 正常结束：`running → completed`
- 异常结束：`running → failed`
- 用户取消：活动状态转为 `cancelled`

服务重启时，`pending` 保持不变；全局暂停状态仍按现有方式持久化，不会因重启自动开跑。

## 模块职责

### 任务管理器

- 创建任务时只保存 `pending`，不加入队列。
- 提供单个开始和批量开始操作，只有这里能把 `pending` 转为 `queued`。
- 全局暂停先冻结调度，再等待运行任务退出。
- 保留现有并发控制、重试和删除逻辑，导出阶段改为本地图片保存。

### 浏览器管理器

- 采集上下文默认使用无窗口模式。
- 按平台维护独立账号目录和上下文。
- 提供关闭全部采集上下文、打开平台登录窗口、关闭平台登录窗口三个明确操作。
- 登录窗口与静默采集不同时占用同一平台账号目录。

### 本地图片存储器

- 只负责图片目录、命名、连续序号、原子写入和去重。
- 使用任务的主页账号名作为稳定目录名，不依赖可能变化的展示昵称。
- 通过项目内部索引保存已写入图片的目标路径，用户图片目录内不放置辅助文件。
- 同一博主的并发写入串行化，避免序号冲突和重复覆盖。

### 应用控制层

- 协调任务管理器与浏览器管理器。
- 暂停完成后关闭浏览器；人工登录期间阻止同平台任务启动。
- 页面接口只调用应用控制层，不直接拼接浏览器生命周期。
- 本地运行时提供“打开图片文件夹”操作；云端运行时明确拒绝本机采集，不尝试写入临时目录。

### 页面

- “导入文件”只解析并回填，不再创建任务。
- 增加“加载内置博主（719）”，内置名单与手工输入共用同一预览和创建流程。
- 原“开始采集”改为“加入待采集”。
- 增加待开始数量、单个开始、开始选中和人工登录操作。
- 明确展示“同时运行五个”和“单次最多导入五百条”的区别。
- 移除任务结果下载和完成任务汇总下载，改为“打开图片文件夹”。

## 接口变化

- 创建单个和批量任务的接口保持不变，但返回的任务状态改为 `pending`。
- 新增读取内置博主列表接口，返回去重后的七百一十九个主页地址。
- 新增单个任务开始接口。
- 新增批量开始接口，接收已勾选的任务编号。
- 新增打开平台登录窗口接口。
- 新增打开本机图片根目录接口，只允许打开固定结果目录。
- “我已处理，继续”在重新排队前关闭可见登录窗口。
- 暂停接口在任务全部退出后关闭采集浏览器，再返回成功。

所有开始接口都必须校验任务状态；重复点击不会重复入队。批量操作返回成功数量和被跳过数量，避免部分失败时用户无法判断结果。

## 异常处理

- 文件解析失败：保留当前输入内容，不创建任务。
- 无效或重复链接：在加入前显示统计；创建时由服务端再次校验。
- 暂停期间创建任务：保存为“待开始”，不会运行。
- 浏览器关闭失败：任务暂停结果仍然保存，同时在接口中返回可读错误，便于用户手动处理。
- 登录窗口已经打开：再次点击只复用现有窗口，不重复启动。
- 静默模式不可用：任务失败并给出明确错误，不自动退回可见窗口，避免突然打断用户。
- 图片重复：返回已存在的目标路径，不重新下载或改名。
- 图片写入失败：仅记录在任务错误中，不留下半写入文件；其他图片继续处理。
- 云端环境发起采集：返回“本机采集仅支持在电脑运行”，不写入临时目录。

## 测试与验收

### 自动检查

1. 创建单个或批量任务后状态为“待开始”，采集器未被调用。
2. 单个开始和批量开始只调度目标任务，重复开始不重复入队。
3. 暂停全部会中止任务、保存状态并调用浏览器关闭操作。
4. 服务重启不会自动运行“待开始”任务。
5. 文件导入只回填链接，不请求任务创建接口。
6. 内置名单去重后为七百一十九条，加载时不创建任务。
7. 静默采集启动参数正确，普通采集路径不调用页面前置操作。
8. 人工登录窗口只在显式操作后出现，处理完成后关闭并恢复静默采集。
9. 本地图片按账号分目录并连续编号，点赞未知时使用固定占位文案。
10. 重复图片不重复写入，同一博主并发保存时序号不冲突。
11. 用户图片目录只包含博主子目录和图片，不包含明细表、压缩包或内部索引。

### 人工验收

1. 导入五百条链接后页面仅显示预览，不出现浏览器窗口。
2. 加载内置博主后显示七百一十九条预览，不创建任务、不出现浏览器窗口。
3. 勾选五条开始，只运行这五条，其余保持“待开始”。
4. 运行中点击暂停，采集器专用浏览器退出，用户日常浏览器不受影响。
5. 登录失效时任务等待；点击打开登录窗口、完成登录并继续后，采集恢复为无窗口运行。
6. 完成任务后可从页面打开 `/Users/lijiawei/Pictures/博主图片采集`，图片已按账号归档且没有明细表和压缩包。

## 兼容与边界

- 已存在的 `queued`、`running` 和 `paused` 任务继续按原有恢复规则处理，不迁移成 `pending`。
- 不新增数据库和外部队列，继续使用现有文件存储与内存调度器。
- 不保留旧的任务压缩包下载与完成任务汇总下载流程，新任务直接写入本机图片目录。
- 不实现采集断点续传；暂停后从头运行，保证结果一致性。
- 不保存采集明细表；收藏数、评论数和原文链接不进入最终文件。
- 仍然只采集公开图文内容，视频继续过滤。
