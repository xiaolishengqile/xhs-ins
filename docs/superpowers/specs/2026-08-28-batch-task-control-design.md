# 批量任务控制与浏览器生命周期设计

## 1. 背景与目标

当前采集流程已经支持最多 5 个任务并行执行，但存在以下问题：

- 采集器在返回结果前关闭任务标签页；当浏览器中没有其他页面时，部分系统浏览器会退出，随后媒体下载使用的请求上下文被销毁，出现“请求上下文已释放”或“页面、上下文、浏览器已关闭”。
- 浏览器上下文与任务标签页的生命周期没有分层，任务失败或暂停时也缺少统一清理入口。
- 页面只能手工粘贴少量链接，不能通过文件批量导入。
- 缺少全局暂停与继续能力。
- 缺少一次下载所有已完成任务的能力。

本次改造目标：

1. 每个平台的系统浏览器保持打开，任务完成后只关闭该任务使用的标签页。
2. 标签页必须持续到“页面采集、媒体下载、任务压缩包生成”全部结束后再关闭。
3. 支持从文件导入大量链接，调度器最多同时运行 5 个任务，其余任务排队。
4. 提供全局暂停和继续；暂停时停止正在运行的任务并冻结队列，继续后被暂停任务从头执行。
5. 提供“下载全部已完成任务”按钮，下载点击时已经完成的所有任务。

## 2. 已确认的产品语义

### 2.1 浏览器管理

- 每个平台维护一个持久浏览器上下文，并使用系统默认浏览器程序。
- 每个平台创建一个专用常驻空白页。该页面只用于维持浏览器进程，不会分配给采集任务。
- 每个任务拥有自己的任务页面集合，包括主页、详情页和需要的人机验证页。
- 正常完成时，在媒体下载及压缩包生成完成后关闭任务页面。
- 暂停、取消或失败时，立即关闭该任务持有的页面。
- 等待用户验证时，仅保留验证所需页面；验证完成后继续沿用该页面。
- 只有服务退出时才关闭浏览器上下文和常驻空白页。

### 2.2 全局暂停与继续

- “暂停全部”影响所有正在运行和排队的任务。
- 正在运行的任务收到中止信号，状态变为“已暂停”，并释放页面等运行资源。
- 已排队任务继续保持排队状态，但调度器不再启动新任务。
- “继续全部”解除调度器冻结，将已暂停任务重新排队，并从头执行。
- 已完成、已失败、已取消和等待用户验证的任务不被全局暂停修改。
- 调度器暂停状态写入独立状态文件，服务重启后仍保持暂停，避免重启瞬间误启动队列。

### 2.3 文件导入

- 页面支持上传纯文本或逗号分隔表格文件。
- 系统从文件中提取以 `http://` 或 `https://` 开头的链接；推荐每行一个链接。
- 同一文件内的重复链接自动去重。
- 单次最多接收 500 个唯一链接，防止误上传超大文件造成服务阻塞。
- 无效链接被跳过并返回行号及原因；有效链接正常创建任务，避免一个错误阻止整批任务。
- 批量任务共用页面当前选择的日期范围。
- 批量创建后仍由统一调度器控制，最大并发数固定为 5。
- 不与历史任务去重，允许用户重新采集相同链接和日期范围。

### 2.4 下载全部已完成任务

- 点击按钮时对“已完成”任务做一次快照，之后才完成的任务不进入本次下载。
- 服务实时生成一个总压缩包，其中每个任务保留原有独立压缩包，文件名包含平台、作者和任务编号。
- 不重新下载媒体，也不重新运行任务。
- 如果某个已完成任务的压缩包意外缺失，总压缩包仍包含其他可用任务，并附带清单说明遗漏项。
- 没有可下载任务时按钮禁用；服务端同时返回明确提示，防止绕过页面产生空文件。

## 3. 方案比较与选择

### 方案一：服务端统一调度与批量接口（采用）

由任务管理器维护全局暂停状态、并发队列和任务运行资源；页面只发出批量创建、暂停、继续和下载请求。

优点：刷新页面或关闭页面不会破坏调度状态；暂停语义一致；便于测试和后续增加任务优先级。缺点：需要增加少量服务端状态与接口。

### 方案二：仅在页面端循环创建和暂停任务（不采用）

页面逐条提交链接，并对每个任务分别调用取消或恢复接口。

问题：页面刷新后批量状态丢失；请求过程中可能只暂停一部分任务；队列仍可能在多个请求之间启动新任务，无法保证“冻结全部”。

### 方案三：新增完整批次领域对象（暂不采用）

为每次文件导入创建批次、批次状态、批次归档和批次级数据库结构。

问题：当前需求只需要统一调度和结果集合下载，完整批次模型会显著增加状态同步和迁移成本。接口会保留扩展空间，后续确有批次历史、批次重试等需求时再引入。

## 4. 总体结构

### 4.1 浏览器层

`BrowserManager` 负责平台级持久上下文和常驻页，不再向任务复用常驻页。新增任务会话对象负责：

- 创建并登记任务页面；
- 提供当前浏览器请求上下文给媒体下载器；
- 保留验证页面；
- 正常结束、暂停、取消或失败时幂等清理任务页面；
- 浏览器异常退出时使缓存失效，后续任务可重新创建上下文。

任务会话由任务管理器创建并持有，贯穿采集器与导出器。采集器不得自行关闭属于任务会话的页面。

### 4.2 调度层

任务管理器继续作为唯一调度入口，最大并发数为 5，并增加：

- `paused`：全局调度器是否暂停；
- `pauseAll()`：冻结调度并中止运行任务；
- `resumeAll()`：解除冻结并重新排队已暂停任务；
- 每个运行任务的中止控制器和任务会话；
- 统一的任务结束清理逻辑。

任务新增 `paused` 状态。状态转换如下：

```text
queued -> running -> completed
                  -> failed
                  -> waiting_user
                  -> cancelled
                  -> paused -> queued -> running
```

全局暂停期间允许创建任务，但新任务只进入队列，不会启动。

### 4.3 持久化层

- 任务状态仍按现有方式保存。
- 新增小型调度器状态存储，只记录全局暂停布尔值和更新时间。
- 写入采用临时文件替换方式，避免进程中断留下半个文件。
- 服务启动时先读取调度器状态，再恢复任务，确保暂停状态先于队列调度生效。

### 4.4 导出层

- 单任务导出流程保持现有目录结构和压缩包格式。
- 媒体下载发生在任务会话关闭之前。
- 新增总压缩包生成器，直接把已存在的单任务压缩包流式写入响应，不复制媒体、不生成长期临时总包。
- 总压缩包内增加清单文件，记录任务编号、平台、作者、状态、压缩包文件名及遗漏原因。

## 5. 接口设计

### 5.1 批量创建

`POST /api/tasks/batch`

请求包含链接数组和日期范围。响应包含：

- 成功创建的任务摘要；
- 被跳过链接的原始行号、内容和原因；
- 去重数量；
- 当前调度器暂停状态。

服务端再次执行数量、链接格式、平台和日期校验，不能只依赖页面校验。

### 5.2 获取调度状态

`GET /api/control`

返回是否暂停、最大并发数、运行数、排队数和暂停任务数。

### 5.3 暂停与继续

- `POST /api/control/pause`
- `POST /api/control/resume`

接口应可重复调用。重复暂停或重复继续返回当前状态，不产生错误。

### 5.4 下载已完成任务

`GET /api/tasks/download-completed`

响应为流式总压缩包。快照中没有可用压缩包时返回冲突状态和中文说明。

### 5.5 兼容现有接口

单任务创建、取消、重试、继续、删除和下载接口继续保留。单任务取消与全局暂停含义不同：取消后的任务不会被“继续全部”自动恢复。

## 6. 页面交互

任务创建区域新增文件选择控件和“导入文件”按钮。文件解析后先显示有效链接数、重复数和无效数，再提交有效链接。

任务列表上方新增全局控制区：

- 运行时显示“暂停全部”；
- 暂停时显示“继续全部”，并显示队列已冻结；
- 显示运行、排队、暂停、完成数量；
- 显示“下载已完成任务（数量）”，数量为零时禁用。

页面轮询任务列表时同步获取全局控制状态，多个页面同时打开时能够保持一致。

## 7. 错误处理与资源安全

- 中止信号必须贯穿页面采集、等待、媒体下载和归档步骤。
- 所有任务页面清理均为幂等操作，重复清理不会掩盖原始错误。
- 常驻页不会被任务清理逻辑关闭。
- 浏览器上下文意外关闭后，从管理器缓存中移除；新任务会重新启动上下文。
- 单个媒体下载失败仍按现有行为记录在任务结果中，不导致其他媒体停止下载。
- 批量导入的无效行不会生成任务，并在页面集中展示原因。
- 全局暂停不是“任务成功”，不会生成不完整压缩包。

## 8. 原流程与新流程对比

### 原流程

1. 任务打开主页和详情页。
2. 采集器结束时关闭页面。
3. 导出器随后通过浏览器请求上下文下载媒体。
4. 如果关闭页面导致系统浏览器退出，请求上下文随之销毁，媒体下载失败。

### 新流程

1. 平台浏览器先创建不可分配的常驻空白页。
2. 任务创建独立会话并打开自己的页面。
3. 采集完成后页面继续保留，导出器使用同一上下文下载媒体并生成压缩包。
4. 任务完整结束后统一关闭任务页面，浏览器由常驻页继续保持打开。
5. 暂停、取消或失败则中止当前步骤并清理任务页面；继续任务时从头创建新会话。

## 9. 测试策略

### 9.1 浏览器生命周期

- 常驻页不会作为首个任务页面返回。
- 任务页全部关闭后浏览器上下文仍存活。
- 导出完成前任务页不关闭，导出完成后关闭。
- 暂停、取消、失败均关闭任务页但不关闭常驻页。
- 人机验证只保留验证页。
- 浏览器异常关闭后缓存正确失效。

### 9.2 下载回归

构造“最后一个页面关闭即销毁请求上下文”的测试替身，验证媒体下载发生在页面清理之前，不再出现请求上下文已释放错误。

### 9.3 调度控制

- 暂停会中止所有运行任务并阻止新任务启动。
- 排队任务在暂停期间保持排队。
- 继续后暂停任务从头执行，并仍遵守最多 5 个并发。
- 重复暂停和继续保持幂等。
- 服务重启后恢复全局暂停状态。

### 9.4 文件批量导入

- 支持纯文本和逗号分隔表格内容。
- 验证链接提取、去重、无效行报告和 500 条上限。
- 大于 5 条时仅运行 5 条，其余排队。
- 全局暂停期间导入只创建排队任务。

### 9.5 汇总下载

- 只包含点击时已完成且压缩包存在的任务。
- 不包含运行中、暂停、失败、取消和等待验证的任务。
- 文件名安全且不重复。
- 单个压缩包缺失时仍能下载其他结果，并在清单中说明。
- 没有结果时不生成空压缩包。

### 9.6 页面行为

- 文件选择、导入摘要、暂停、继续及汇总下载按钮状态正确。
- 刷新页面后仍显示真实调度状态。
- 错误提示为中文且可操作。

## 10. 完成标准

- 可通过文件一次导入最多 500 个唯一链接。
- 实际同时运行任务数不超过 5。
- 暂停后不再启动新任务，运行任务变为已暂停并关闭任务页。
- 继续后已暂停任务从头开始运行。
- 单任务媒体下载不再因任务页提前关闭而丢失浏览器请求上下文。
- 任务结束只关闭任务页，系统浏览器保持打开。
- 可一次下载当前所有已完成任务的结果。
- 新增行为有自动化测试覆盖，原有任务创建、单任务控制和下载功能保持可用。
